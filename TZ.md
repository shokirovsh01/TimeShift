# Техническое задание: TimeShift

**Платформа тайм-банкинга для IT-специалистов**
Версия документа: 1.0
Стек: Django 5.2 · HTML · Tailwind CSS · SQLite/PostgreSQL

---

## 1. Обзор концепции

**TimeShift** — веб-платформа тайм-банкинга (time banking), где единицей расчёта
служит **минута** участника. Время каждого человека — одинаково ценно, поэтому
час помощи новичка и час помощи эксперта оцениваются одинаково.

Базовый цикл ценности:

1. Участник **создаёт задачу** и указывает награду в минутах.
2. Другой участник **берёт задачу** и выполняет её.
3. При закрытии задачи минуты **переводятся** с баланса автора балансу исполнителя.
4. Полученными минутами участник **платит** другим за помощь.

Дополнительно минуты можно получать «из воздуха» через **тайм-кран** и
**ежедневные квесты**, а также тратить на **PRO-статус**.

### Цели продукта

| # | Цель | Критерий |
|---|------|----------|
| G1 | Децентрализованный обмен помощью внутри IT-сообщества | Работающая доска задач с созданием, откликом и закрытием |
| G2 | Удержание участников через ежедневные механики | Тайм-кран и квесты доступны каждый день |
| G3 | Мотивация к репутации и видимости | Отзывы, репутация, лидерборд, подписки |
| G4 | Монетизация внутри экономики | PRO-статус за 3000 минут |

### Целевая аудитория

- Разработчики, дизайнеры, тестировщики и другие IT-специалисты.
- Участники комьюнити, готовые обмениваться услугами без денег.

## 2. Ключевой функционал

### 2.1 Доска задач (Bounty Board)

Основной экран платформы — список задач (`/`).

| Функция | Описание | Реализация |
|---------|----------|------------|
| Создание задачи | Автор указывает название, описание, награду (минуты) и required-скиллы | `BountyCreateView`, шаблон `bounty/create_task.html` |
| Просмотр и фильтры | Фильтрация по статусу (`open`, `in_progress`, `completed`) и по скиллу через GET-параметры `?status=&skill=` | `BountyListView` |
| Отклик (взять в работу) | Любой авторизованный пользователь, кроме автора, берёт открытую задачу; статус меняется на `in_progress`, назначается исполнитель | `TakeTaskView` (`GET /task/<pk>/take/`) |
| Закрытие задачи | Только автор может закрыть задачу `in_progress`; выполняются проверки лимитов и баланса, создаётся договор помощи, минуты переводятся | `CompleteTaskView` (`GET /task/<pk>/complete/`) |
| Отмена | Статус `cancelled` предусмотрен моделью | `BountyTask.STATUS_CHOICES` |

**Статусы задачи:** `open` → `in_progress` → `completed` (или `cancelled`).

**Карточка задачи** показывает: статус-бейдж, награду в минутах, описание,
теги скиллов, автора (с Telegram-ссылкой), дату, исполнителя и контекстную
кнопку действия («Взять в работу» / «Закрыть задачу»).

### 2.2 Тайм-кран (Time Faucet)

Ежедневный «кран», выдающий бонусное время.

| Параметр | Значение |
|----------|----------|
| Размер бонуса | **+20 минут** за клик |
| Кулдаун между кликами | **20 минут** |
| Дневной лимит крана | **300 минут** (15 кликов) |
| Сброс лимита | При первом клее в новый день (`last_bonus_date`) |
| Эндпоинт | `GET /collect-bonus/` → `CollectBonusView` |

Каждый клик засчитывается в квест «Забрать бонус тайм-крана» и отображается
прогресс-баром `daily_bonus_minutes / 300` в профиле.

### 2.3 Ежедневные квесты

Каждый день участник выполняет **три действия** и получает **+60 минут** один раз в день.

| # | Квест | Условие | Где начисляется |
|---|-------|---------|-----------------|
| 1 | Создать задачу | `created_tasks >= 1` | `BountyCreateView.form_valid` |
| 2 | Закрыть задачу | `completed_tasks >= 1` | `CompleteTaskView` |
| 3 | Забрать бонус тайм-крана | `faucet_clicks >= 1` | `CollectBonusView` |

Прогресс хранится в `DailyQuestProgress` (одна запись на пользователя на день).
Награда выдаётся методом `check_and_reward()` строго один раз
(`is_reward_claimed`), только при выполнении **всех трёх** условий.

### 2.4 PRO-статус

| Параметр | Значение |
|----------|----------|
| Стоимость | **3000 минут** с баланса |
| Эффект | Дневной лимит переводов **720 мин** вместо **120 мин** |
| Визуал | Бейдж «★ PRO» в профиле и лидерборде |
| Эндпоинт | `POST /buy-pro/` → `BuyProView` |

Повторная покупка запрещена (сообщение «У вас уже есть PRO-статус»).

### 2.5 Система переводов с дневными лимитами

Перевод минут происходит **только при закрытии задачи**.

| Параметр | Обычный участник | PRO-участник |
|----------|------------------|--------------|
| Дневной лимит переводов | **120 минут** | **720 минут** |
| Учёт | `daily_spent_minutes` + `last_spend_date` | аналогично |
| Сброс | При наступлении новой даты | При наступлении новой даты |

Правила закрытия задачи:

1. Закрыть задачу может **только автор**, и только в статусе `in_progress`.
2. Проверяется дневной лимит: `daily_spent + reward <= limit`.
3. Проверяется баланс: `balance_minutes >= reward`.
4. Награда списывается с баланса автора и зачисляется исполнителю.
5. Исполнителю начисляется **+10 к репутации**.
6. Создаётся запись `HelpContract` (договор помощи).

### 2.6 Отзывы и репутация

- Авторизованный участник может оставить **отзыв с оценкой от 1 до 10**
  другому пользователю (`POST /user/<username>/review/`, `AddReviewView`).
- Отзыв на самого себя запрещён.
- Поле: `rating` (1–10), необязательный `text`.
- **Репутация пересчитывается автоматически** сигналом на `post_save`/`post_delete`
  модели `Review`: `reputation = round(avg(rating))`, при отсутствии отзывов — `0`.
- Дополнительно при закрытии задачи исполнителю начисляется `+10` к репутации.

### 2.7 Ледерборд

- Эндпоинт: `/leaderboard/`, `LeaderboardView`.
- Сортировка: `Profile.objects.order_by('-balance_minutes')`.
- В шаблоне выводится **топ-10** участников: ранг, аватар, имя, специализация,
  бейдж PRO, репутация (`⭐ N/10`) и баланс (`⏳`).
- Рангам 1–3 присваивается золотой/серебряный/бронзовый градиент.

### 2.8 Система подписок на авторов

- Модель `Follow`: `follower` подписан на `following`, уникальность пары.
- Переключение подписки: `POST /user/<username>/follow/` → `ToggleFollowView`
  (создать или удалить запись).
- Подписка на себя запрещена.
- При **создании новой задачи** все подписчики автора получают
  **уведомление** (`Notification`) с названием задачи и наградой
  (сигнал `notify_followers_on_new_task`).
- Заготовка интеграции с Telegram-ботом присутствует в коде
  (закомментирован блок отправки по `telegram_id`).

### 2.9 Профиль участника

- Просмотр своего профиля (`/profile/`) — баланс, репутация, PRO, тайм-кран,
  квесты, кнопка покупки PRO.
- Публичный профиль (`/user/<username>/`) — «О себе», специализация,
  Telegram, список задач автора, кнопка подписки.
- Редактирование (`/profile/edit/`) — логин, имя, фамилия, аватар (≤ 2 МБ),
  специализация, био, Telegram-ник (валидация уникальности).

### 2.10 Регистрация и авторизация

- Регистрация: `UserCreationForm` (`/register/`).
- Вход/выход: стандартные Django-вьюхи (`/login/`, `/logout/`).
- Страница «О нас»: `/about/`.

## 4. Функциональные требования (FR)

| ID | Требование |
|----|------------|
| FR-01 | Система должна позволять зарегистрированному пользователю создавать задачи с наградой в минутах и списком скиллов |
| FR-02 | Система должна позволять пользователю взять открытую задачу в работу (кроме собственных) |
| FR-03 | Система должна позволять автору закрывать задачу `in_progress` при выполнении проверок лимита и баланса |
| FR-04 | Система должна переводить минуты от автора к исполнителю при закрытии задачи и создавать `HelpContract` |
| FR-05 | Система должна выдавать +20 минут через тайм-кран не чаще одного раза в 20 минут и не более 300 минут в день |
| FR-06 | Система должна начислять +60 минут за полное выполнение трёх ежедневных квестов один раз в день |
| FR-07 | Система должна позволять покупать PRO-статус за 3000 минут и увеличивать дневной лимит переводов до 720 минут |
| FR-08 | Система должна ограничивать дневные переводы 120 минутами для обычных участников |
| FR-09 | Система должна permetать отзывы с оценкой 1–10 и пересчитывать репутацию автоматически |
| FR-10 | Система должна выводить лидерборд топ-10 по балансу минут |
| FR-11 | Система должна позволять подписываться на участников и уведомлять подписчиков о новых задачах |
| FR-12 | Система должна форматировать баланс в человекочитаемый вид (`X ч. Y мин.`) |

| Слой | Технология |

| Backend | **Django 5.2** (CBV: `ListView`, `CreateView`, `DetailView`, `View`) |

## 7. Критерии приёмки

- [ ] Пользователь может зарегистрироваться, войти и получить профиль с балансом 60 мин.
- [ ] Можно создать задачу, взять чужую открытую задачу и закрыть её.
- [ ] При закрытии задачи минуты списываются у автора и поступают исполнителю.
- [ ] Закрытие блокируется при превышении дневного лимита (120/720) или нехватке баланса.
- [ ] Тайм-кран выдаёт +20 мин не чаще, чем раз в 20 минут, и максимум 300 мин в день.
- [ ] За три квеста в день начисляется ровно +60 мин, повторно — нет.
- [ ] PRO покупается за 3000 мин и поднимает лимит переводов до 720 мин.
- [ ] Отзыв изменяет репутацию автора отзыва автоматически (среднее с округлением).
- [ ] Ледерборд показывает топ-10 по балансу.
- [ ] Подписчик получает уведомление при публикации новой задачи автором.
- [ ] Баланс отображается в формате `X ч. Y мин.` / `Y мин.`.
