[ ] 1.2. Создать и активировать виртуальное окружение (venv).
[ ] 1.3. Установить базовые зависимости:

[ ] 1.4. Создать Django-проект (`config` или `devtime_core`) и основное приложение (`bounty_board` или `core`).
[ ] 1.5. Подключить базу данных PostgreSQL в `settings.py` (на первых порах для скорости можно стартовать на SQLite, а перед деплоем переключить на Postgres).
[ ] 1.6. Настроить базовый шаблон `base.html` с подключением Tailwind CSS.

[ ] 2.4. Создать модель `BountyTask` (задача на бирже: автор, исполнитель, заголовок, описание, цена в часах, статус, дата).

ЭТАП 4. БИРЖА ЗАДАЧ (BOUNTY BOARD) И ЛОГИКА СДЕЛОК (ЯДРО ПРОЕКТА)
-------------------------------------------------------------------
Цель: Реализовать полный цикл сделки и автоматический пересчет часов.

[ ] 4.1. Главная страница (Дашборд): вывод всех открытых задач (`status='open'`) с фильтрацией по навыкам.
[ ] 4.2. Страница создания новой задачи:
         - Проверка: хватает ли у создателя часов на балансе (`time_balance >= reward_hours`). Если нет — выводить красивое предупреждение.
[ ] 4.3. Механика «Взять задачу в работу»:
         - Кнопка на карточке задачи.
         - Защита: автор не может взять собственную задачу.
         - При нажатии статус меняется на `in_progress`, а поле `performer` заполняется текущим пользователем.
[ ] 4.4. Механика «Подтвердить выполнение» (Транзакция времени):
         - Кнопка доступна только автору задачи.
         - При нажатии открывается мини-форма с коротким отзывом.
         - Срабатывает атомарная транзакция (`transaction.atomic()`):
           1) У заказчика списываются часы (`time_balance -= reward_hours`).
           2) Исполнителю начисляются часы (`time_balance += reward_hours`) и растет `reputation`.
           3) Статус задачи меняется на `completed`.
           4) Автоматически создается запись в `HelpContract`.

-------------------------------------------------------------------
